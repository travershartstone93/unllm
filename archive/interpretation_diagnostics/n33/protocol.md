# N33 · N32 usage audit

Use the same five pinned vanilla snapshots, FP32, greedy settings, native chat/seq2seq interface, decoder suffix slicing, no repairs, original batch sizes and N32 full-task token budget. Verify token IDs against the tokenizer's native chat encoding / seq2seq encode, check slice boundaries, and retain raw answers. Compare two general controls (capital of France, French-to-English “Je t’aime”), and one exact-copy control on the output syntax. Probe the comparison alone on the 20 executable development requests with ordinary language labels and no grammar. For the full 24, keep the N32 prompt and add four worked request/answer examples (N30 training IDs t03a, t17a, t18a, t17b in that order) and an Answer cue. Score plain and grammar-constrained outputs with the original scorer. These are unchanged weights with in-context demonstrations, not another zero-shot run. Select no model, fit no weights and make no product changes. This checks prompt/interface sensitivity on a known development set; it cannot establish an optimal prompt for each family.

Additional diagnostic for FLAN-T5-base and mT0-small after the four-shot checks: keep all 24 requests and weights fixed, but ask short questions separately for outcome, aggregate, relation, threshold source, structure, and missing choice. Rank ordinary-language answers by mean teacher-forced log likelihood including EOS. Generate a fixed integer without gold candidates when needed. Use a shared deterministic serializer and the original exact-meaning scorer. This is an exploratory change of task interface, not a clean isolation of one prompt feature or a new model ranking.
