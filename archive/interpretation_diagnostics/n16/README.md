# N16 development baseline

The subsequent [contract integration and English diagnostics](bridge.md) record the implementation and its verification. The results below describe the pre-change baseline.

The first N16 milestone froze a prospective 32-request evaluation and replayed the public N11 and N14 diagnostics using the existing product binaries. No N16 acceptance prompt was submitted to an interpreter. The fixture author had knowledge of earlier experiments. This is a development holdout, with independent confirmation still pending. The 12 reserved positive rows impose exclusions on future training data. A contamination check becomes possible once those data exist. | Public test | Outcome | What it establishes |
| --- | --- | --- |
| Six N11 English tasks through both target modes | 0/6 programs in either language. Four requests reached the 128-reading limit with grounding rejections. Two timed out unpacking grammar readings. | The English route stopped before construction. Candidate presence outside the explored readings is unknown. |
| Identical N11 structured example contracts through the normal code route | All 12 calls rejected the field `examples`. | The entry point does not dispatch this existing sequence-function contract to the algorithm constructor. |
| Direct construction from N11 types and eight examples | 3/6 passed ten reserved cases per target. Clamping, consecutive deduplication and position-weighted summation exhausted search. | Even with more evidence than English supplies, construction succeeds on only part of this suite. |
| Supplied IR for the three exhausted tasks | All three passed their eight original and ten reserved cases in each target, 54 checks per language. | The backend can express and execute these calculations. The constructor still has to discover them. |
| Eight N14 English construct requests | 0/8 programs in either language. Five lacked an analysis within budget. Two stopped during grounding and one at the reading limit. | No single parser replacement follows from these failures. |
| Supplied N14 count-positive function | Both targets passed the same four execution cases as the original trial. | Positive control for a function containing a conditional inside a loop. |

**Decision.** Start with the three publicly verified sequence functions as integration controls. Give the normal code entry point an unambiguous way to delegate an explicitly typed algorithm contract to the existing C++ constructor. Confirm that the same contracts retain the same outcomes on both paths, including genuine search exhaustion. Keep a callable sequence function distinct from a stream utility. Input parsing, line-oriented output and print effects in N11's English are additional requirements. No evidence from this replay equates these interfaces.

Then test whether an independently specified *behavioral* contract without hidden scoring examples can reach construction. A contract-format reference for the pure computation subset is [SyGuS](https://sygus-org.github.io/language/). Its specification covers a synthesis target, constraints and a grammar of possible implementations. The project already has an algorithm constructor, so an adapter to its existing interface is the first reuse opportunity. SyGuS adoption, ACE removal and training a new parser each need a separate measured benefit. Preserve failures in both public suites as baselines for the English comparison.

## Reproduction

The measured checkout was based on `f336d71869aec4afdc69db49ff5cfe5ef8f36df0` with existing working-tree changes. Use binary hashes for the precise executable identity. The public [N11 fixtures and replay instructions](../../algorithm_ir/paired_routes/README.md) describe the English and direct constructor arms. For the additional bridge check, submit the serialized `contract` object from each public task as the argument to `build/unllm --json --code cpp` and repeat for Python. For the three [supplied IR controls](controls), run `build/unllm --algorithm check IR CONTRACT /usr/bin/python3` with the original construction and reserved rows concatenated into the contract's examples. For N14, the eight exact prompts are in the measured JSON. Repeat the CLI calls in fresh isolated storage; the original supplied control is linked in [N14's experiment log entry](../../../docs/EXPERIMENT_LOG.md). The local file `.state/n16.path` locates the complete raw replay, including stderr and sessions.
