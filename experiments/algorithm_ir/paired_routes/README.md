# N11 paired coding routes

The frozen tasks, construction examples and reserved outputs are in [tasks.json](tasks.json). [Results](results.json) contains both English decisions per task, structured search counts and the hashes returned by the dual-target reserved checker. The implementing assistant chose these tasks from the existing integer-sequence signature. They share input rows and familiar algorithm families. This is a development comparison.

Use the in-tree CLI with the model off, server disabled and Python target set to /usr/bin/python3. For each task run `build/unllm --json --code python PROMPT` and repeat with cpp. Independently pass only the contract object to `build/unllm --algorithm construct FRESH_SESSION CONTRACT /usr/bin/python3`. For a validated selection write its ir field to a file and replace the contract's examples with the reserved rows. Run `build/unllm --algorithm check IR RESERVED_CONTRACT /usr/bin/python3`. The run used two task workers and a separate fact store per task. The checkout's .state/paired-routes.path locates the raw replies, sessions and trial runner.

English produced no executable for scoring. The example-driven route verified offset, count_zero and negative_prefix, each on ten reserved inputs in both languages. For floor_zero, skip_repeats and weighted_sum the current search exhausted its bounded grammar before producing a candidate. This does not establish a limitation of the underlying IR. Four English prompts cited the integer concept at the reading bound; both target languages timed out on the two longer prompts. Parser timing can vary. The routes receive different evidence and currently invoke different construction paths.
