# N16 contract integration

The normal coding CLI now recognizes a sequence-function contract with input type `ints`, an output type and examples. It calls the same native bounded search used by the algorithm constructor. Search failures retain their classification, and a successful function is emitted in the requested language. Validation checks that target against the supplied examples. Python emission without a configured interpreter remains labeled `emitted`. Successful contracts participate in normal context replay. A contradictory revision leaves the previous successful program available.

```sh
./build/unllm --json --code cpp '{"input":"ints","output":"int","examples":[{"input":[],"output":"0"},{"input":["4","3"],"output":"7"},{"input":["-2"],"output":"-2"}]}'
```

The public replay restored all six direct-constructor outcomes through both target modes. Offsetting each element, counting zeros and the running negative count passed all ten reserved rows each in both languages. For each winner the two product outputs had the same IR and their source hashes matched the independently executed reserved checker. Clamping, consecutive deduplication and position-weighted sum exhausted the same search, with identical candidate counts. The six-task replay also passed after the final build. [Outcomes](bridge-results.json) · [Replay script](replay-bridge.sh)

**Behavior without examples.** Independently supply existing stream contracts for three public tasks. Use numeric records, a map with `x + 1` and output values for offset; a filter with `x == 0` and output count for zero counting; and a map with `0 if x < 0 else x` and output values for clamping. All six generated CLI programs read the reserved inputs from stdin and wrote the expected output on ten cases each. The stream contracts and bounded sequence search are different construction mechanisms. Clamping succeeds through the stream expression route even though example-based sequence search exhausts. The established stream contract supports finite decimal numbers and these checks exercise its shared integer domain. [Reserved executions](stream-reserved.tsv)

**English parser diagnostic.** We built the released C++ UDPipe 1.4.0 parser and ran its pretrained English EWT model on eight public construct requests. It returned trees for 8/8. Fifteen of 24 predeclared direct dependency edges matched. Only two requests matched every specified edge. One mismatch was an alternate grammatical label for the word “for”; another attached the conditional statement to “make” instead of nesting it under the loop. Tree availability measures less than correctly bound requirements. The dependency parser stays isolated.
