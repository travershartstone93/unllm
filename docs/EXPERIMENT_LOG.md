# unllm upgrade experiment log

Use this file to find what was tested, which variables changed, what happened, and which decision followed. Add future experiments here when fixing their design, then complete the same entry after scoring. The linked reports retain per-case results, commands and fixtures. Historical entries cover documented upgrade experiments and validation runs through the 2026-11-18 checkpoint `f336d71`. Where a run lacks an exact revision or date, its report or saved run identifies it.

**Current findings.** Normal code generation now reproduces the example-based constructor's results in both target languages. Lightweight semantic parsing and adjusted ranking verified five of eight new stream requests but did not transfer to the broader frozen coding fixture (0/24 programs). Typed filtered reductions now pass four contracts in both languages without construction examples. The normal CLI also consumes the saved N22 interpretations offline, with all eight executable requests verified in both languages. The equivalent unaided English cutoff request still fails. [N16–N18 results](../archive/interpretation_diagnostics/n16/broad-results.md)

**How to read the counts.** The denominator is named in each entry. Interpreting a request correctly, generating a candidate, passing construction examples, and passing independent execution checks are different outcomes. A top-five *usable hit* in the retrieval trials means at least one candidate passed under the adapter being tested. When every candidate fails construction, the number of selected programs scored on reserved inputs is zero. Several rows reuse a suite or examine a known failure. Keep their scores separate.

## Adding the next result

Give each experiment one stable ID. Before examining outcomes, record the question, what changes between arms, the baseline, the variables held fixed and the decision criterion. After the run, append measured results to the same entry and link the immutable evidence. Give a changed task set, scoring rule or post-hoc diagnostic its own entry. Preserve failures and identify the replacement for a superseded run.

| Field | What to record |
|---|---|
| Identity | ID, date, owner, status and related earlier entry. Use proposed, running, completed or superseded. |
| Question and design | Hypothesis, changed variable, named arms, frozen controls and criterion for adoption. |
| Inputs and environment | Code revision and any uncommitted diff or binary hashes, corpus/model snapshot, dataset origin, task split, seeds, hardware and tool versions where relevant. |
| Procedure | Entry point or replay command, budgets, shortlist size, repetition count, timing boundaries and independent oracle. |
| Results | Numerators and denominators per arm, wrong acceptances, abstentions/exhaustions, unscored cases, regressions and resource cost. For retrieval, record rank, selection, binding, missing dependencies and execution verdict separately. |
| Decision and evidence | What the result changes, its limits, protocol, per-task artifacts and checksums. Mark missing historical measurements as unrecorded. |
